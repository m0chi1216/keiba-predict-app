# 頭数で正規化した着順回帰の損失案

## 対象と確認条件

2026-10-11。ユーザーの「回収率ではなく、レース頭数で正規化した着順を当てたい」という要望について、README、src/predict.py、src/betting_strategy.py、configs/strategies/v8_regression_softmax.jsonを静的に確認した。対象の既存モデルは models/v8_regression/model_rank_23.pkl。学習コード・学習評価CSVは本リポジトリに含まれないため、既存の学習目的関数、教師値の定義は未確認。設定JSONの回収率は購入戦略の評価値であり、学習損失が回収率である証拠ではない。

## 設計案（未実装）

レース j の実際の出走頭数を N_j、馬 i の確定着順を r_ij とし、教師値を y_ij = r_ij / N_j とする。値が小さいほど上位。例として8頭立ての4着、16頭立ての8着はいずれも0.5、最下位は1となる。正規化するのは教師値であり、損失は予測値と教師値の誤差として定義する。

初期案は全馬平均の MSE = sum((prediction_ij - y_ij)^2) / 全馬数。頭数にかかわらず同じ相対位置の誤差を同じスケールで扱うが、各馬が等重みなので多頭数レースは総寄与が大きい。レースごとの寄与も揃える場合は L = mean_j(mean_i((prediction_ij - y_ij)^2)) とする。全馬平均に対応する学習器では各馬の sample_weight = 1 / N_j で同等の目的を表現できる。

各レースの1着を厳密に0、最下位を1に揃えたい場合は (r_ij - 1) / (N_j - 1) という別案がある。こちらは N_j > 1 が必要。要望どおり単純に頭数で割る案は r_ij / N_j とし、2つの定義を混在させない。

頭数は登録頭数ではなく実出走頭数とする。レース全体から頭数を確定し、その後で教師値不明の行を扱う。取消・除外は頭数に含めず、中止・失格の教師値付与は別途方針を決める。同着は公式着順を使用する。欠損着順を自動的に最下位へ置換しない。特徴量・教師値・重みは同じ行で揃え、レースを途中で分割しない。

## 既存アプリへの影響

静的確認では、回帰の予測値を predicted_rank に格納し、昇順で候補順位を決める。スコアは softmax(-predicted_rank / temperature)。正規化着順でも小さい値が上位という方向は整合するが、新モデルへの置換には再学習が必要であり、推論時に既存出力を頭数で割るだけでは学習目的は変わらない。

新モデルでは予測値のスケールが変わる可能性があるため、temperature（既存設定0.042925）・購入しきい値は検証データで再調整する。正規化着順やそのsoftmax値を校正済み勝率と扱わない。モデル・エンコーダー・設定・結果は日付と条件を付けて新規保存し、既存モデルを上書きしない。

本作業では静的調査と数式設計のみ実施し、コード・モデル・設定は変更していない。精度向上や回収率の変化は未測定。MSEは着順そのものの一致や1着的中率を直接最適化するものではない。
